## How the site is put together

A static site: HTML, JS and CSS, no build step; every script is Python standard library only. One shell (`assets/js/shell.js`) adds the sidebar, top bar, theme switch and search to every page, with two themes (Dark and Paper, `assets/css/tokens.css`). Chapters are typeset at run time, the architecture lives in `architecture.html` (old `architecture/*.html` pages redirect there), and `404.html` is the not-found page.

**Before you push:** `python scripts/check_site.py` and the unit tests in `scripts/` (the list is in `.github/workflows/site-check.yml`). The gate also checks size budgets (200 KB per page) and accessibility basics. Details: `UPDATING.md`, "Quality gate, accessibility and budgets".

## Team to-do (live shared list)

`todo.html` is a shared to-do, workload view and timeline. It also edits the master timeline dates that `roadmap.html` shows, so both pages always agree.

- No login. Anyone with the site link can read and edit, on purpose, so the team can fix each other's work.
- Data lives in a hosted Redis through `api/todo.js` (a Vercel serverless function, no npm packages).
- Changes show up for everyone within a few seconds. Offline edits are kept on the device and sync when back online.
- Safety: deletes go to a trash, the server keeps a snapshot of the whole list for every day for 35 days, and Settings has a download/restore backup.

One-time setup (about 2 minutes):

1. Vercel dashboard, your project, **Storage**, **Create Database**, pick **Upstash for Redis** (Marketplace), connect it to this project (all environments).
2. That adds the `KV_REST_API_URL` and `KV_REST_API_TOKEN` environment variables automatically.
3. Redeploy the project once. Open `todo.html`: the pill at the top should say **Live**. The first visit loads the starter data from `data/todo.json`.

Until the database is connected, the page still works but only on the one device, and says so in the pill.

Master timeline items live in `data/master-timeline.js`. Edit that file to add or rename items.

## Keeping the Atlas in step with the code

The Overview, Files, Functions, History, Map, API, Agents, Infra and Explore pages, plus `data/summary.md`, are generated from `data/census.json` by `scripts/refresh_atlas.py` (Python standard library only). The census itself is made by MiniMe's `scripts/codebase_census.py`.

**Automatic:** push a new `data/census.json` to `main`. `.github/workflows/refresh-atlas.yml` re-renders the pages, commits them, and Vercel deploys that commit. One-time setup: GitHub, Settings, Actions, General, Workflow permissions, **Read and write**.

**To make a new census and refresh everything in one command**, from this repo with a clean MiniMe checkout next to it (the folder must be named `MiniMe`):

```
pip install tree-sitter tree-sitter-javascript pyyaml
python scripts/refresh_atlas.py --census-from ../MiniMe
```

It refuses to replace `data/census.json` if the new one is untrustworthy (no tree-sitter, no PyYAML, or uncommitted files in MiniMe, which the census would count). Then commit and push.

Other commands: `python scripts/refresh_atlas.py` refreshes from the census you already have, `--check` changes nothing and exits 1 if anything is out of date, and `python scripts/test_refresh_atlas.py` runs the tests.

**Search (Ctrl/Cmd+K).** The command palette reads `data/index/*.json`, which `scripts/build_index.py` builds from `content/nav.json`, the chapter headings, the glossary and `data/census.json`. `refresh_atlas.py` rebuilds it with the pages, so the automatic route above keeps it current; run `python scripts/build_index.py` on its own after you edit `nav.json` or a chapter, and `--check` to see whether it is stale. Operators: `>` pages, `#` book headings, `/` files, `@` functions and classes, `:` API routes, `?` help. Keys: `t` theme, `?` shortcut sheet, `g` then `o` / `e` / `b` / `s` to jump. The palette needs `http(s)`, so test it with `python scripts/serve.py`, not by opening the file.

**Chapter reader (P04).** The 15 chapter pages are typeset at run time by `assets/js/reader.js` and `assets/css/reader.css`; `shell.js` loads them only on pages that have a chapter banner or a `.doc article`, and **no `doc-*.html` file is edited**, so the external page builder can keep overwriting them. It gives serif/sans and five text sizes (the **Aa** button), an **On this page** rail built from the headings (`]` toggles it; a bottom sheet below 1200 px), a chapter bar with progress and previous / next, remembered reading position with a "resume" toast, typed callouts (`Purpose:`, `Rule:` ...), scrollable tables with a sticky header and a filter box above 25 rows, copy-link on headings, a copy button on code, and print rules. Its switches are in `content/reader.json`: per-chapter `numbered`, the table filter threshold and the callout patterns. `python scripts/list_headings.py <chapter>` prints heading ids (for placing figures later). Tests: `python scripts/test_reader.py`.

**Library and glossary (P05).** `docs.html` is the book's table of contents, drawn in the browser by `assets/js/library.js` from `data/index/book.json`: one card per chapter with read time, sections, tables, last-built date, a progress ring and a Continue button (both read what the chapter reader remembered), five part filters, a search over chapter titles and section headings, and the reading paths. `book.json` is written by `scripts/build_index.py` from each chapter's own banner (`.bk-desc`, `.bk-meta`, the "Built ... from commit ..." line), so the counts cannot drift; the two interactive design specs have no counts and say so. `glossary.html` shows `content/glossary.json` (term, aliases, category, short, long, `see`, optional `match` and `needs_review`). In a chapter the first use of each term per section gets a dotted underline and a tooltip (hover, focus or tap; `Esc` closes); a term with `"match": "off"` (ordinary words like *wave*) appears on the glossary page only, `"cs"` matches the exact case, and `"glossary": false` in `content/reader.json` turns tooltips off for a chapter or everywhere. A `see` is a chapter id (`doc-rulebook`, or `doc-rulebook#1-the-15-golden-rules`), a repo file, or `file::symbol`; `content/reading-paths.json` uses the same targets, and `check_site.py` fails if any of them is missing. Add a term by editing `content/glossary.json`, then `python scripts/build_index.py` so the palette finds it. Tests: `python scripts/test_library.py`.

**Figures (P06).** Diagrams are put into the chapters at run time by `assets/js/figures.js` (loaded by `shell.js` after the reader), so no `doc-*.html` file is edited. Each chapter has an optional manifest `content/figures/<chapter id>.json`: `{id, after, place, type, src | code, caption, alt, wide, size}`, where `after` is a heading id (`python scripts/list_headings.py <chapter>`), `type` is `archify` (an `architecture/*.html` page in an iframe; `size` is the pixel size of its SVG), `svg` (a file in `content/figures/svg/` or inline `code`, drawn with the theme tokens) or `mermaid` (needs `python scripts/vendor_mermaid.py` once). Figures are numbered per chapter (Figure 4.2), follow the Dark / Paper theme, and have an Expand viewer (wheel / pinch zoom, drag, `+ - 0 1`, `Esc`). `alt` is required and `check_site.py` validates every manifest and SVG. Tests: `python scripts/test_figures.py`.

**Overview (P07).** `index.html` is a shell: `assets/js/overview.js` and `assets/css/overview.css` draw it from `data/index/vitals.json` (the census half is written by `refresh_atlas.py`, the graph half by `refresh_graph.py`), `content/subsystems.json` (directory table), `content/system/request-path.json` ("Anatomy of a request", shared with the System page) and the hand-written `content/overview/*.html`. `scripts/test_overview.py` tests the helpers in Node.

**Topology (P08).** The "System at a glance" diagram on the Overview: `assets/js/topology.js` and `assets/css/topology.css` draw it from `content/topology.json` (the hand-curated layout), `data/index/vitals.json` `census.topology` (box size = code lines, from `refresh_atlas.py`) and `data/graph/folders.json` (line width = graph links, from `refresh_graph.py`). Hover or focus a box for its details, click it for links, follow one request through it, or open the M2C client into its 9 parts. `?edit=1` lets you drag boxes and copy the new layout as JSON. `scripts/test_topology.py` tests the helpers in Node and the layout against the census; the rules are in `check_site.py`.

**Architecture views (P26).** `arch-view.html` and `assets/js/arch/` draw every view of the architecture model (P25: `data/arch/`) in plain SVG, no library: structure (three zoom levels, an optional flow laid over it), step flows in swimlanes, sequences, lifecycles and the API surface. Every step shows the status of the code it cites (fresh, stale, broken, unverified), an AI-written label and links to Explorer, source, GitHub and VS Code; a flow that is not written yet shows only what is derived and says so. A chapter draws one inline with a figure of type `arch`. Pan, zoom, bottom sheet and drag live in `assets/js/svgview.js`, shared with the topology. `scripts/test_arch_render.py` tests the pure parts in Node.

**System page (P09).** `architecture.html` is the home of the architecture: `assets/js/system.js` (DOM) on `assets/js/system-model.js` (pure) builds one section per view of the model, in the order of `content/system/views.json`, which also holds the only hand-written text (what you are looking at, how to read it, the legend, the book sections to read). Each section embeds the live diagram (expandable, with a link to the interactive view), lists the numbered steps or transitions of its flow with the code each one cites, shows a freshness badge (fresh, stale, broken, unverified, not written yet) with the AI-written label and confidence, and lists where the book disagrees with the code (`doc_conflicts`). The top of the page is the **Anatomy of a request** stepper, read from flow `request-path` and, until that flow is written, from `content/system/request-path.json`. Section ids are view ids, because the palette links to `architecture.html#<view id>`. The 8 hand-made files in `architecture/` stay as a collapsed block of links until P23. `scripts/test_system.py` tests the pure parts in Node and the rules of the page and its prose.

**Project wing (P21).** The ten Project pages (roadmap, to-do, build, progress, decisions, consistency, journey, tests, health, finance) carry `data-wing="project"` and load `assets/css/project.css` after their own inline CSS. It points their old variables (`--p`, `--ln`, `--tx` ...) at the shared tokens, so Dark and Paper both work, and gives `.card`, `.pill`, tables, inputs and focus the shared look; every selector is scoped to the wing and nothing changes layout, and `sync.js` is untouched. **Decisions** (`decisions.html`) is now static HTML, one card per decision with a stable id that can be linked (`decisions.html#G-07`): the 15 Golden Rules are `G-01` ... `G-15` (the old `G1` ... `G15` keys in this browser's `localStorage` are moved once, and `#G7` still lands on `#G-07`); the other ids (`T1`, `R1`, `MK-D1`, `MT-D1`, `F1-D1` ...) were already stable. In a chapter, a `Rule 7:` or `Golden Rule 7:` callout now links to `decisions.html#G-07` (`hrefTemplate`, `hrefLabelTemplate` and `hrefMax` in `content/reader.json`). **Progress** shows each matching file as a link to the Explorer, and **Health** opens the exact symbol for "Largest functions" and adds a `symbols` link to each Risk board file. These pages are still written by hand, not by a generator, so a new file or function there is linked by hand (`scripts/test_project.py` fails if a link points at something that is not in the census). Tests: `python scripts/test_project.py` (the jsdom page test needs `npm install --prefix scripts/explorer_tests jsdom`, otherwise it is skipped).

**Embedded source and code links (P12).** `scripts/refresh_source.py` copies MiniMe's source into `data/src/` at the census commit (read from git, secret-scanned, `update_all.py` runs it), and `assets/js/links.js` turns "this file, these lines" into an Explorer link, an in-site source link, a GitHub permalink and a VS Code deep link, whichever of them can be built. The link icon in the top bar sets where your MiniMe folder is (saved in this browser only) and which editor opens. `content/config.json` holds the GitHub repo, the default editor and the `embedSource` switch; `data/src-denylist.txt` lists what is never copied. Details are in `UPDATING.md` ("Embedded source and code links"). Tests: `python scripts/test_refresh_source.py` and `python scripts/test_links.py`.

**Syntax colours on the Source tab (P14b).** `assets/js/explorer/highlight.js` colours the embedded source with highlight.js 11.11.1, vendored under `assets/vendor/highlight/` (the engine plus 13 grammars, 72 KB; pinned by sha512/sha256 in `scripts/vendor_highlight.py`, which also re-downloads it: `python scripts/vendor_highlight.py`, check with `--check`). Only the grammar a file needs is loaded (Python ~24 KB in all), the plain text appears first and the colours follow, and a "Syntax colours" checkbox turns them off (remembered in this browser). The coloured lines are built as DOM text nodes, never as HTML, and every line reads exactly like the plain one (checked over all 1,100+ embedded files). If the vendored files are missing, or the file is not code, the tab stays plain. Colours come from the Atlas tokens, so Dark and Paper both work. Tests: `python scripts/test_explorer.py` and `python scripts/test_vendor_highlight.py`.

**Symbol panel (P14c).** Opening a symbol (`#/f/<path>::<name>?tab=symbols`, or a click in the Symbols list or on a call) shows a card above the list: the signature, the AI summary (else the docstring's first line, each labelled), parameters (names, types and defaults from the census, descriptions from the note), returns, raises, side effects, what it **calls** and who it is **called by**, the line ranges the note cites, and View source / GitHub / VS Code / Copy buttons. Calls that resolve to a file of the repo are links to that symbol's own panel; the rest are listed by name. Callers come from `data/code/callers/<shard>.json` (loaded only when a symbol is open; tests are grouped apart) and cover Python only. Both are static and best effort, so "nothing calls this" never means "unused" (routes, decorators and dynamic calls are not seen), and the panel says so. A class shows its bases, methods and constructor callers. Without a note the panel still shows every census fact. Code: `assets/js/explorer/symbol.js` (card) and `symbolDetail()` in `model.js` (pure). Tests: `python scripts/test_explorer.py`.

**Audit mode (P16).** In the Explorer, open a symbol and press `r` (reviewed), `c` (concern) or `n` (to do); the same key again clears the mark, and a one-line comment can be added in the Audit card of the symbol panel. A review records the census `hash` of the symbol, so when that symbol changes the check turns into **needs re-review** (the mark is kept; press `r` after reading the new code to renew it). Marks show on the Symbols rows, as `✓ 3/12` on file and folder rows of the tree, and in the inspector; `#/audit` (Explorer, "Audit" link under the tree) lists totals, concerns, re-reviews and anything whose symbol has left the census, compares every mark with the census on demand ("Check against the census"), exports and imports JSON (newest mark wins on import) and copies the concerns as Markdown for an issue. Marks live in this browser (`localStorage` key `minime_audit_v1`). **Sharing is opt-in** (checkbox on the audit page): marks then go through `sync.js` to the same store as the To-do page as records of kind `audit` (`api/todo.js` accepts that one extra kind; the id is a hash of `path::qual` because ids may not contain `:` or `/`), the newest change wins, and there is no login, as for the To-do list. Local marks are only uploaded when you press the button. Code: `assets/js/explorer/audit.js` (rules and store, no DOM) and `auditui.js` (drawing, keys). Tests: `python scripts/test_explorer.py` (`audit.mjs`, page scenarios `audit*`) and `python scripts/test_todo_api.py`.

**Not refreshed, because the census cannot supply it.** From the Graphify graph (now the `graph` half of `data/index/vitals.json`): the graph nodes and links, "Graph hubs", the API "frontend callers" column (carried over per route, blank for routes added since) and the Explore connection edges (carried over per file). From other inputs: Tests, Health, Data model, Tables, Graph, Roadmap, Finance, Decisions and the document pages. Each of those keeps its own "Built ... from commit ..." label, so every page says how old it is.
